# Bukaake — Project History & Agent Memory

## Rules for Agents
1. **Check Before Planning**: Always read this file before formulating plans or changing code to avoid repeating past mistakes.
2. **Log Code Changes**: Append a brief summary ("just the gist") of modified files and objectives after each change.
3. **Log Mistakes**: When the user flags an error (*"don't do this"*, *"not what I expected"*, etc.), immediately log it under **Mistakes** with the strict rule to prevent repetition.

## Mistakes (Never Repeat)
- **[MISTAKE] Release Notes**: Never write in project folder (use task artifacts only). Never use `>` blockquotes or emojis. Never include download links. Never hype the tone—use professional, technical language. Mandatory format: Title, Target, Summary, Details.
- **[MISTAKE] Multi-File Commits**: Never lump unrelated files into a single commit. Inspect files, group by category/similarity, stage group-by-group, compose per-file notes + batch message, and execute commits.
- **[MISTAKE] Architecture Plans in Chat**: Never output plans directly into the chat response. Always write architectural and implementation plans to task artifacts in the artifact directory, and provide a concise reference link in chat.
- **[MISTAKE] Automatic Commits**: Never execute git commits autonomously unless the user explicitly asks to commit ("commit this", "commit changes", etc.). Even if implementing or following a workflow plan, stop after writing and verifying changes; wait for the user to explicitly request a commit.
- **[MISTAKE] Timer Polling for Background Tasks**: Never set a loop of `schedule` timers to poll status on a running background command or build. Repeated timer execution keeps the agent turn active and prevents user messages from delivering (they become queued in the IDE). Launch the command and end the turn immediately; the system automatically wakes the agent upon task completion.
