# Bukaake — Project History & Agent Memory

## Rules for Agents

1. **Check Before Planning**: Always read this file before formulating plans or changing code to avoid repeating past mistakes.
2. **Log Code Changes**: Append a brief summary ("just the gist") of modified files and objectives after each change.
3. **Log Mistakes**: When the user flags an error (*"don't do this"*, *"not what I expected"*, etc.), immediately log it under **Mistakes** with the strict rule to prevent repetition.

## Mistakes (Never Repeat)

- **[MISTAKE] Solid Fills & Shifting Collapsed Beacons**: Never render collapsed state indicators with solid opaque or semi-opaque circular discs when a glowing outline vector icon (`ri-error-warning-line`) is requested. The background must remain 100% transparent with glow applied exclusively to the lines of the glyph and ring via `filter: drop-shadow`. Furthermore, never auto-move or hide the collapsed beacon when the metadata/information drawer opens—the collapsed beacon must stay firmly anchored in the top-left corner (`top: 20px; left: 20px;`) with equal insets at all times, while only the expanded shortcut card aligns horizontally alongside the drawer (`top: 50px`).
- **[MISTAKE] Gaudy Neon / Saturated Buttons in Minimal Glass UI**: Never use solid multi-color gradient fills (e.g. violet-fuchsia-cyan discs) or brightly saturated purple/violet button text inside minimalist frosted glass viewports. Match the application's ghost button design system (translucent monochrome frosted glass `background: rgba(255, 255, 255, 0.08)` / `rgba(26, 32, 44, 0.08)`, subtle hover brightness, and standard monochrome font icons like `ri-information-line` matching the titlebar ghost buttons) while using soft ambient box-shadow halos for glow effects rather than solid neon fills.
- **[MISTAKE] Unequal Corner Insets**: Never position corner-anchored HUDs or floating beacons with unequal top/left insets (e.g. 52px left vs 10px top) or floating awkwardly deep into the canvas. Strictly anchor corner elements with equal 20px margins: in Mode 1, `left: 20px; top: calc(var(--titlebar-height, 42px) + 20px);` (20px from left edge and 20px below titlebar); in Mode 2, `left: 20px; top: 20px;` (20px from screen left and top edges).
- **[MISTAKE] Icon Font Faux-Bold / Thickening**: Never declare `font-weight: bold / 600 / 700` on parent buttons or containers containing font icons (Remix Icon `ri-*` or SVG) without explicitly locking `font-weight: normal !important; font-style: normal;` on the icon element (`i`, `svg`). Applying font-weight to the parent causes the browser to synthesize artificial faux-bold strokes on the icon, degrading crisp line glyphs into thick, blurry, distorted blobs. Always isolate bold weights to the text label span (e.g. `.draw-pill-label`) and ensure icon glyphs remain `font-weight: normal !important`.
- **[MISTAKE] Release Notes**: Never write in project folder (use task artifacts only). Never use `>` blockquotes or download links. Never repeat prior release items. Mandatory 4-part format: Title, Target, Summary (casual/non-pro README-style bullet points with feature icons), Detailed Changes (strictly professional, objective technical depth with zero emojis and covered commits).
- **[MISTAKE] Multi-File Commits**: Never lump unrelated files into a single commit. Inspect files, group by category/similarity, stage group-by-group, compose per-file notes + batch message, and execute commits.
- **[MISTAKE] Architecture Plans in Chat**: Never output plans directly into the chat response. Always write architectural and implementation plans to task artifacts in the artifact directory, and provide a concise reference link in chat.
- **[MISTAKE] Automatic Commits**: Never execute git commits autonomously unless the user explicitly asks to commit ("commit this", "commit changes", etc.). Even if implementing or following a workflow plan, stop after writing and verifying changes; wait for the user to explicitly request a commit.
- **[MISTAKE] Timer Polling for Background Tasks**: Never set a loop of `schedule` timers to poll status on a running background command or build. Repeated timer execution keeps the agent turn active and prevents user messages from delivering (they become queued in the IDE). Launch the command and end the turn immediately; the system automatically wakes the agent upon task completion.
